# Поигрулькины

Голосовой чат для небольшой компании (до 8 человек), в духе Mumble. Работает
в локальной сети и через интернет. Написан на Rust.

Есть сервер, графический клиент и консольный клиент для Windows.
Версия для Android будет дальше (см. [план](#план)).

## Что понадобится (Windows 11)

1. **Rust** версии 1.90 или новее. Если `cargo` пишет *«rustup could not choose
   a version of cargo to run… no default is configured»*, значит rustup установлен,
   но ни один тулчейн не выбран. Установите и выберите стабильный:
   ```powershell
   rustup default stable-x86_64-pc-windows-msvc
   rustc --version    # проверка
   ```
   Если тулчейн уже стоял: `rustup update`.
2. **Visual Studio Build Tools** с компонентом «Разработка классических приложений на C++».
   Обычно ставится вместе с Rust: без него не работает даже `cargo build` для hello world.
3. **CMake** — нужен, чтобы собрать кодек Opus (это C-библиотека):
   ```powershell
   winget install Kitware.CMake
   ```
   После установки откройте **новое** окно терминала, чтобы обновился `PATH`.
4. **NASM** — ассемблер для кодека H.264 (демонстрация экрана). Без него кодек
   работает в 3–5 раз медленнее, поэтому сборка без NASM останавливается
   с подсказкой:
   ```powershell
   winget install NASM.NASM
   setx NASM "C:\Program Files\NASM\nasm.exe"
   ```
   Без прав администратора установщик кладёт NASM не в `Program Files`, а в
   `%LOCALAPPDATA%\bin\NASM` — тогда в `setx` укажите этот путь (сборка сама
   подскажет, где нашла `nasm.exe`). Затем — новое окно терминала. Если
   программа уже собиралась без NASM, пересоберите кодек:
   `cargo clean -p openh264-sys2`.

## Сборка

```powershell
cargo build --release
```

Первая сборка занимает несколько минут: графический клиент тянет за собой Tauri.

Готовые программы появятся в `target\release\`:
- `poigrulkiny.exe` — графический клиент (нужен всем);
- `poigrulkiny-server.exe` — сервер (нужен одному человеку, у кого он будет запущен);
- `poigrulkiny-cli.exe` — консольный клиент (для проверок и экспериментов).

Друзьям не обязательно ставить Rust: достаточно передать им `poigrulkiny.exe`.
Графическому клиенту нужен WebView2, в Windows 11 он уже встроен.
Если при запуске Windows ругается на отсутствующий `VCRUNTIME140.dll`, нужно
установить «Microsoft Visual C++ Redistributable».

Тесты: `cargo test`.

## Графический клиент

Запустите `poigrulkiny.exe`, введите адрес сервера (как для консольного
клиента, например `192.168.1.10` или `100.101.102.103`) и своё имя.
Серверы из вашей локальной сети программа находит сама и показывает под полем
адреса вместе с числом участников: достаточно нажать на нужный.
Через интернет вставляется код приглашения от хоста (или адрес Tailscale).
Всё введённое запоминается.

Шестерёнка вверху открывает настройки: тема (как в системе, светлая или
тёмная), цвет оформления, микрофон, динамики или наушники и шумоподавление.

### Защита от подмены сервера

Разговор зашифрован (TLS 1.3 внутри QUIC). Чтобы никто не мог незаметно
встать между вами и сервером, программа при первом подключении запоминает
сертификат сервера, а при следующих сверяет его, как это делает SSH.

- У каждого сервера есть **код**, например `5FE2-EA5E-A088-824E`. Он виден
  в комнате под адресом сервера, у хоста — в карточке «Вы — сервер», у
  `poigrulkiny-server` — в его окне при запуске.
- Если сертификат изменился, программа не подключится сразу, а покажет
  предупреждение с кодами «было» и «стало». Спросите у хоста его код:
  - совпал со «стало» — хост переустановил программу или удалил файлы
    сервера, жмите «Доверять»;
  - не совпал — кто-то выдаёт себя за сервер. Не подключайтесь.
- Запомненные сертификаты лежат в `known_servers.txt` в папке программы
  (`%APPDATA%\io.github.addfsw.poigrulkiny`). Это обычный текстовый файл,
  строку можно удалить.
- Код меняется, только если удалить файлы сертификата сервера
  (`server_cert.der`, `server_key.der`). Поэтому их не нужно удалять без причины.

### Через интернет без Tailscale: код приглашения

Если белого IP ни у кого нет, программа может сама «пробить» NAT роутеров:
1. Хост создаёт комнату, раскрывает карточку «Вы — сервер» и ставит галочку
   **«Доступ через интернет по коду приглашения»**. Появится код вида
   `poi-YuK8i_a25KN6…`, его кнопкой «копировать» можно отправить друзьям в мессенджер.
2. Друг вставляет код в поле «Сервер или код приглашения» и жмёт «Подключиться».

Код постоянный: отправили один раз, и он работает в следующие разы, пока
у хоста те же компьютер и сертификат сервера. В код входит отпечаток
сертификата, поэтому подменить сервер нельзя даже при первом подключении.

Как это работает:
- **STUN.** Каждая сторона спрашивает у публичного STUN-сервера (Google,
  Cloudflare), с какого внешнего адреса и порта её видно.
- **Почтовый ящик.** Стороны обмениваются этими адресами через бесплатный
  сервис [ntfy.sh](https://ntfy.sh), без регистрации. Тема в ящике — длинная
  случайная строка из кода приглашения.
- **Встречные пакеты.** Обе стороны одновременно шлют пакеты друг другу.
  Каждый роутер принимает встречные пакеты за ответы на свои, и соединение
  идёт напрямую. Голос через сторонние сервисы не ходит.

Ограничения:
- **Не пробивается «симметричный» NAT**, когда роутер выдаёт каждому собеседнику
  новый внешний порт. Так бывает у мобильного интернета и у части
  провайдеров. Программа это распознаёт и пишет. Тогда остаётся Tailscale или VPS.
- **Сторонние сервисы.** Пока галочка включена, программа обращается к STUN-серверам
  Google/Cloudflare и к ntfy.sh. Они видят ваш внешний IP, но не разговор.
- **Только IPv4.**

Для экспериментов адреса сервисов можно заменить переменными окружения
`VWF_STUN_SERVERS` (через запятую) и `VWF_SIGNAL_URL` (свой ntfy-сервер).
Отдельный сервер включает то же опцией `--internet` и печатает код приглашения
при запуске. Консольный клиент принимает код вместо адреса:
`poigrulkiny-cli connect poi-… --name Петя`.

Пробивка проверена на стенде с настоящим NAT Linux: два «домашних
роутера» с межсетевым экраном, свои STUN-сервер и почтовый ящик. За первым
роутером хост и ещё один друг, за вторым — двое друзей; все трое заходят по
одному коду одновременно. `sudo scripts/nat-lab/nat-lab.sh cone` — подключаются
все трое (сосед хоста — напрямую по локальному адресу). `… symmetric` — сосед
подключается, а двое за «симметричным» NAT честно получают сообщение, что
пробить не вышло. С настоящими домашними роутерами и
настоящими ntfy.sh/STUN программа на момент написания не проверялась.

### Своя комната без отдельного сервера

Кнопка **«Создать комнату на этом компьютере»** запускает сервер прямо внутри
программы, и вы сразу в нём. Запускать `poigrulkiny-server.exe` не нужно.
- Друзья из вашей локальной сети увидят комнату в списке («Имя — комната»).
- Остальным скажите адрес из карточки «Вы — сервер этой комнаты» (кнопка
  «копировать» рядом). Через Tailscale это адрес вида `100.x.y.z`.
- **При первом создании комнаты Windows спросит про брандмауэр** для
  `poigrulkiny.exe`, разрешите. Если друзья не могут подключиться,
  откройте порты 47777 и 47778 командой из раздела про сервер ниже.
- Карточка «Вы — сервер» свёрнута, адреса для друзей видны по нажатию.
  Там же галочка **«Эхо»**: сервер возвращает каждому его собственный голос.
  Удобно проверить связь и звук, пока никого нет (как `poigrulkiny-server --echo`).
- Создатель комнаты — **хост** (корона у имени). В меню «⋮» у каждого
  участника он может **заглушить его для всех** (сервер перестаёт пересылать
  его голос, сам участник видит «хост заглушил вас») или **выгнать**
  (нужно подтвердить). Выгнанный может подключиться снова: это не бан.
- «Закрыть комнату» (нужно нажать два раза) или закрытие программы
  отключает всех. Гости увидят «сервер остановлен».
- Если на компьютере уже запущен `poigrulkiny-server`, комнату создать не получится:
  порт занят. Подключайтесь к нему как обычно.
- Сертификат встроенного сервера хранится в
  `%APPDATA%\io.github.addfsw.poigrulkiny`.

В комнате:
- зелёное кольцо вокруг аватара — человек говорит (вокруг своего — идёт передача);
- ползунок под именем собеседника — его громкость, от 0 до 200 %.
  Громкость запоминается по имени;
- внизу — панель, как в Discord: ваш аватар, имя и состояние, а справа
  иконки (при наведении появляется подсказка):
  - микрофон и наушники — выключить ваш микрофон или звук собеседников.
    Остальные видят это значками в вашей строке. Стрелка рядом — выбрать
    другое устройство: например, переключиться на только что подключённые
    наушники. Разговор при этом не прерывается;
  - монитор — показать экран (см. ниже);
  - ползунки — окно «Голос»: режим передачи, порог с индикатором громкости,
    клавиша рации, шумоподавление и усиление голоса;
- передача (в окне «Голос»):
  - **Голосом** — передача включается, когда вы говорите громче порога.
    Порог подберите ползунком: черта должна быть выше шума комнаты и ниже голоса;
  - **Всегда** — микрофон передаёт всё время;
  - **Рация** — передача идёт, пока зажата клавиша. Нажмите кнопку «Клавиша»,
    затем нужную клавишу, например `F8`. Клавиша работает, даже когда окно
    свёрнуто или вы в игре, но пока выбран этот режим, в других программах
    она срабатывать не будет;
- полоска в окне «Голос» — громкость вашего микрофона. Черта на ней — порог
  активации;
- «Усиление голоса» (в окне «Голос», включено по умолчанию) подтягивает тихий
  микрофон до нормальной громкости — до +20 дБ, плавно и только по речи, чтобы
  не раздувать шум в паузах. Слишком громкий голос не хрипит: пики
  прижимаются ограничителем. Порог активации и индикатор показывают громкость
  микрофона до усиления;
- в настройках во время разговора есть «Диагностика звука»: сбои микрофона
  и вывода, а по каждому собеседнику — задержка буфера, потери и опоздавшие
  пакеты. Если звук прерывается, по тому, какие числа растут, видно, где
  проблема: у микрофона, у вывода или в сети;
- «Шумоподавление» (там же, где усиление) убирает из вашего микрофона гул
  вентилятора, шум улицы, стук клавиатуры. Включено по умолчанию. Шум
  убирается до детектора голоса, поэтому в режиме «Голосом» передача не
  включается от шума комнаты;
- вкладка «Чат» — текстовый чат комнаты. Enter отправляет, Shift+Enter —
  новая строка, ссылки открываются в браузере. Кто зашёл позже, видит
  последние 100 сообщений. Пока чат закрыт, на вкладке видно, сколько
  непрочитанных;
- иконка монитора внизу — демонстрация экрана: выберите монитор или окно,
  качество (720p, 1080p или как есть) и плавность (15 или 30 к/с). У вас в
  строке появится «показываете экран», а у остальных — кнопка «Смотреть».
  Экран открывается в отдельном окне: его можно растянуть или унести на
  второй монитор; двойной щелчок или F11 — на весь экран. Пока никто не
  смотрит, экран не снимается и трафик не тратится. Кнопкой с монитором в
  своей строке можно посмотреть, что видят остальные;
- короткие сигналы — кто-то вошёл или вышел, пришло сообщение в чат, вы выключили или включили
  микрофон или звук. Выключаются в настройках («Звуки событий»). Пока у вас
  выключен звук, о входе и выходе людей программа тоже молчит;
- если связь пропала (моргнул Wi-Fi, перезапустился роутер), программа не
  выкидывает из комнаты, а пишет «Связь пропала. Возвращаюсь в комнату…» и
  пытается подключиться заново полторы минуты. Если сервер нас отключил сам
  (хост закрыл комнату или выгнал), переподключения нет.

Крестик окна сворачивает программу в трей (значок рядом с часами), разговор
при этом продолжается. Щелчок по значку открывает окно, а его меню умеет
выключить микрофон или звук и выйти из программы. Если удобнее, чтобы крестик
закрывал программу, выключите это в настройках. Повторный запуск программы не
открывает вторую копию, а показывает уже работающую.

Для разработки интерфейса удобно запускать так (окно с консолью для логов):
```powershell
cargo run -p vwf-app
```
Интерфейс лежит в `app\ui\` (обычные HTML, CSS и JavaScript).
После правок достаточно перезапустить эту команду.

Установщик (`.exe`-инсталлятор) можно собрать через tauri-cli, но это
не обязательно, хватает и самого `poigrulkiny.exe`:
```powershell
cargo install tauri-cli --version "^2" --locked
cd app
cargo tauri build
```

## Шаг 1. Проверка звука без сети

```powershell
cd target\release
.\poigrulkiny-cli devices      # список микрофонов и устройств вывода
.\poigrulkiny-cli loopback     # говорите и слушайте себя
```

**Наденьте наушники**, иначе звук из колонок попадёт обратно в микрофон
и начнёт свистеть. Эхоподавления пока нет.

Внизу показывается индикатор громкости микрофона. Голос передаётся, только
когда громкость выше порога (по умолчанию −45 dBFS). Если слова обрезаются,
порог нужно понизить. Если передаётся шум комнаты, порог нужно повысить:

```powershell
.\poigrulkiny-cli loopback --vad-db -50
.\poigrulkiny-cli loopback --no-vad          # передавать всегда
```

Можно послушать, как программа справляется с плохой сетью:

```powershell
.\poigrulkiny-cli loopback --sim-loss 10 --sim-jitter-ms 40
```

Здесь 10 % пакетов теряется, а остальные приходят с задержкой от 0 до 40 мс.
Джиттер-буфер сам подстроится под такую сеть. Его текущую задержку покажет
команда `s` + Enter. Можно задать задержку вручную, например `--jitter-ms 20`,
и послушать, как растёт количество «бульканий».

Другие устройства выбираются по части имени из списка `devices`:

```powershell
.\poigrulkiny-cli loopback --input "USB" --output "Наушники"
```

## Шаг 2. Разговор через сервер

### Запуск сервера

На компьютере, который будет сервером:

```powershell
.\poigrulkiny-server
```

Сервер выведет адреса, по которым к нему можно подключиться. Например:

```
сервер слушает UDP 0.0.0.0:47777
друзья могут подключаться по одному из адресов:
    192.168.1.10:47777    (Ethernet)
    100.101.102.103:47777 (Tailscale)
```

Сервер использует два UDP-порта:
- 47777 — сами разговоры;
- 47778 — ответы на поиск серверов в локальной сети.

При первом запуске Windows спросит разрешение для брандмауэра, его нужно дать.
Если друзья всё равно не могут подключиться или не видят сервер в списке,
откройте порты вручную в PowerShell **от имени администратора**:

```powershell
New-NetFirewallRule -DisplayName "Poigrulkiny" -Direction Inbound -Protocol UDP -LocalPort 47777,47778 -Action Allow
```

Другие параметры сервера:
- `--name "Комната Пети"` — название, которое видят при поиске (по умолчанию имя компьютера);
- `--no-discovery` — не отвечать на поиск;
- `--admin-token <секрет>` — права хоста получит тот, кто подключится с этим
  секретом: `poigrulkiny-cli connect ... --admin-token <секрет>`. В графическом
  клиенте права хоста есть у того, кто создал комнату кнопкой.

При первом запуске сервер создаёт рядом с собой файлы `server_cert.der`
и `server_key.der` (TLS-сертификат). Не удаляйте их и никому не отправляйте:
по сертификату клиенты узнают сервер. Если файлы пропадут, у всех появится
предупреждение «сертификат сервера изменился».

Консольный клиент тоже запоминает сертификаты (в
`%APPDATA%\poigrulkiny\known_servers.txt`). Если сертификат изменился, он
откажется подключаться. Сверив код с хостом, подключитесь с
`--trust-new-certificate`.

### Проверка в одиночку

В режиме `--echo` сервер возвращает каждому его собственный голос. Так можно
проверить всю цепочку через сеть, не дожидаясь друзей:

```powershell
.\poigrulkiny-server --echo
# в другом окне:
.\poigrulkiny-cli connect 127.0.0.1 --name Я
```

В консольном клиенте `t текст` пишет в чат, а демонстрация экрана
включается при подключении:
```powershell
.\poigrulkiny-cli screens                          # что можно показать
.\poigrulkiny-cli connect 127.0.0.1 --name Я --share monitor:65537
.\poigrulkiny-cli connect 127.0.0.1 --name Я --share --share-height 720
```
Без значения `--share` показывает первый экран из списка.

### Если клиент пишет «сервер не отвечает»

1. Убедитесь, что `poigrulkiny-server` запущен **в отдельном окне** и не закрылся с ошибкой.
   Окно сервера должно оставаться открытым всё время разговора.
2. Проверьте, что сервер слушает порт:
   ```powershell
   netstat -ano -p udp | findstr 47777
   ```
   Пустой вывод означает, что сервер не запущен или запущен на другом порту.
3. Запустите сервер и клиент с подробным журналом. Журнал покажет,
   доходят ли пакеты до сервера:
   ```powershell
   set RUST_LOG=debug
   .\poigrulkiny-server --echo
   ```
   (в PowerShell вместо `set` используйте `$env:RUST_LOG="debug"`)

### Подключение друзей

**В одной локальной сети** (дома, в общежитии):

```powershell
.\poigrulkiny-cli discover                          # найти серверы в сети
.\poigrulkiny-cli connect 192.168.1.10 --name Петя
```

**Через интернет** (белого IP ни у кого нет). Проще всего — код
приглашения (см. «Через интернет без Tailscale»). Если пробить NAT не
получается, есть Tailscale:

1. Все ставят [Tailscale](https://tailscale.com/download) (есть для Windows и Android)
   и входят в одну сеть (tailnet). Владелец может пригласить остальных
   или расшарить им компьютер с сервером.
2. Подключаются по адресу из диапазона `100.x.y.z`, который показывает сервер
   (его также видно в приложении Tailscale):
   ```powershell
   .\poigrulkiny-cli connect 100.101.102.103 --name Петя
   ```

Tailscale сам пробивает NAT. Если напрямую не получается, он пускает трафик
через свои ретрансляторы. Вместо Tailscale подойдёт ZeroTier. Лимиты бесплатных
тарифов у них меняются, проверьте актуальные.

Команды в консоли клиента (букву и Enter):
- `m` — выключить или включить микрофон;
- `s` — текущая задержка джиттер-буфера для каждого собеседника.

Ctrl+C завершает программу.

## Как это устроено

```
 Клиент A                              Сервер                         Клиент B
 микрофон (WASAPI, cpal)                                              динамики
   │ моно, ресемплинг до 48 кГц                                          ▲
   ▼                                                                     │
 кольцевой буфер ─► кадры 20 мс ─► шумодав ─► VAD ─► Opus      микшер (сумма всех)
                                            │                            ▲
                                            ▼                            │
                                  QUIC-датаграмма ──► пересылка ──► джиттер-буфер
                                  [seq][opus]        всем, кроме   + декодер Opus
                                                     отправителя   (на каждого собеседника)
```

| Крейт | Что внутри |
|---|---|
| [`proto`](proto/src/lib.rs) | Константы (48 кГц, кадр 20 мс), управляющие сообщения, формат голосовых пакетов, протокол поиска в локальной сети |
| [`server`](server/src/lib.rs) | QUIC-сервер: одна комната, пересылка пакетов. Звук не декодирует |
| [`nat`](nat/src) | Пробивка NAT: STUN, почтовый ящик (ntfy), коды приглашений |
| [`client`](client/src) | Библиотека клиента (звук, кодек, сеть) и консольная программа |
| [`app`](app) | Графический клиент на Tauri: команды в [`src/main.rs`](app/src/main.rs), интерфейс в [`ui/`](app/ui) |

Устройство клиента:
- [`audio.rs`](client/src/audio.rs) — захват и воспроизведение через `cpal`. Аудиоколбэки
  только перекладывают сэмплы в lock-free кольцевые буферы, ничего тяжёлого в них нет.
- [`resample.rs`](client/src/resample.rs) — приведение частоты звуковой карты к 48 кГц и обратно.
- [`pipeline.rs`](client/src/pipeline.rs) — передатчик (шумодав RNNoise, VAD, кодер Opus
  с FEC) и микшер (по джиттер-буферу и декодеру на каждого собеседника).
- [`jitter.rs`](client/src/jitter.rs) — джиттер-буфер: порядок пакетов, потери, опоздания,
  подстройка задержки.
- [`net.rs`](client/src/net.rs) — подключение к серверу.
- [`call.rs`](client/src/call.rs) — всё вместе: устройства, кодер, микшер и соединение.
  Им пользуются оба клиента, консольный и графический.
- [`discovery.rs`](client/src/discovery.rs) — поиск серверов в локальной сети.

Почему так:
- **QUIC (`quinn`)** даёт на одном UDP-порту и надёжный канал для команд,
  и ненадёжные датаграммы для голоса. Шифрование TLS 1.3 встроено.
  Потерянный голосовой пакет переотправлять бессмысленно: к моменту
  переотправки его время проигрывания уже прошло.
- **Opus** — стандартный кодек для голоса в интернете (Discord, WebRTC, Mumble).
  Включён in-band FEC: в каждый пакет добавляется сжатая копия предыдущего кадра,
  поэтому одиночные потери восстанавливаются. Остальные потери «замазывает» PLC
  (packet loss concealment) декодера.
- **Шумоподавление RNNoise** (`nnnoiseless`, перенос на Rust). Небольшая
  нейросеть по спектру каждых 10 мс оценивает, где голос, а где шум, и
  приглушает шумные полосы частот. Стоит меньше 1 % одного ядра процессора
  и около 10 мс задержки. Синтетическое «белое» шипение глушит слабо: она обучена
  на реальных шумах вроде вентиляторов и улицы.
- **Поиск в локальной сети** — обычный UDP-broadcast: клиент кричит на всю сеть
  «есть тут серверы?» (порт 47778), каждый сервер отвечает лично ему своим
  названием, портом и числом участников. Broadcast не выходит за пределы
  локальной сети и не проходит через Tailscale, поэтому для интернета адрес
  вводится вручную.
- **Сервер только пересылает пакеты**, звук не смешивает. Каждый клиент
  сам декодирует и смешивает голоса. При 8 участниках сервер отдаёт около
  8 × 7 × 32 кбит/с ≈ 1,8 Мбит/с, это посильно для домашнего интернета.

### Задержка

Из чего складывается задержка от микрофона до чужих наушников:

| Этап | Сколько | Чем управляется |
|---|---|---|
| Захват (период WASAPI) | ~10 мс | Windows |
| Шумоподавление | ~10 мс | галочка «Шумоподавление», `--no-denoise` |
| Накопление кадра | 20 мс | размер кадра Opus |
| Алгоритмическая задержка Opus | ~6,5 мс | кодек |
| Сеть | 1–2 мс в локалке, 20–80 мс через интернет | расстояние, провайдер |
| Джиттер-буфер | ~10 мс в локалке, больше в плохом Wi-Fi | подстраивается сам, `--jitter-ms` |
| Ожидание начала кадра микшером | 0–20 мс, в среднем 10 | — |
| Буфер воспроизведения | 30 мс | `--playback-ms` |
| Буфер вывода WASAPI | ~10–20 мс | Windows |

В локальной сети получается около 100 мс. Mumble с настройками по умолчанию
работает в том же диапазоне.

Как это сделано:
- **Адаптивный джиттер-буфер.** Номер кадра растёт каждые 20 мс, даже в тишине.
  По нему получатель знает, когда кадр был записан, и измеряет, насколько
  неровно приходят пакеты. Задержка подбирается так, чтобы 95 % пакетов
  успевали вовремя. Редкие опоздания закрывают FEC и PLC Opus.
- **Без опроса по таймеру.** Аудиоколбэк будит поток кодера сразу, как только
  набрался кадр, а поток микшера — сразу, как только звуковая карта забрала звук.
- **Старт без «хвоста».** Звук, записанный до старта кодера, выбрасывается.

Если появляются сбои вывода (`вывод: сбоев звука`), увеличьте `--playback-ms`
до 30–40. Если звук «булькает» на плохом Wi-Fi, задайте постоянную задержку,
например `--jitter-ms 60`.

## Ограничения текущей версии

- Нет эхоподавления, поэтому нужны наушники.
- Первому подключению к серверу приходится верить на слово (см. «Защита
  от подмены сервера»): если подмена была уже тогда, программа её не заметит.
- Одна комната на сервер.
- Пробивка NAT не работает с «симметричным» NAT (мобильный интернет, часть
  провайдеров), своих ретрансляторов у программы нет.
- Ресемплинг линейный (для голоса достаточно).
- Демонстрация экрана без звука: звук игры или видео собеседники не слышат.
  Игры в эксклюзивном полноэкранном режиме могут показываться чёрным
  экраном — переключите игру в «оконный без рамки».
- Кадры демонстрации идут через сервер: каждому зрителю 3–6 Мбит/с. Если
  смотрят четверо, а сервер у хоста дома, его интернету нужно отдавать
  12–24 Мбит/с.
- Видео сжимается кодеком H.264 (библиотека OpenH264, собирается из
  исходников). Для личного использования это не важно, но распространять
  такую сборку как продукт — вопрос патентных лицензий H.264.
